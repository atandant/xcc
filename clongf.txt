xcc C Long Feature — clongf.txt
================================

SUMMARY
-------

Add signed `long` to xcc as a first-class integer type on x86-64 LP64, using
Option B (integer width + signedness fields on Type) rather than a flat
TY_LONG kind. This is the foundation for later `unsigned`, `short`, and
`sizeof`/`size_t`, without implementing those yet.

Locked product decisions:

    1. pointer subtraction (`p - q`) result type is `long`.
    2. `long` → `int` assignment is silent (C89-permitted narrowing).
    3. `L` / `l` literal suffixes select type `long` (C89 3.1.5).
    4. Refactor codegen load/store/binop helpers to be width-aware *before*
       wiring `long` through sema/parser.

C89 is the normative spec. xcc targets Linux x86-64 SysV ABI where `long` is
64 bits (same width as pointers). Document that ABI choice; do not emulate
32-bit `long`.

Out of scope for this feature:

    - `unsigned`, `unsigned long`, `short`, `long long`
    - full usual arithmetic conversions involving unsigned
    - `typedef`, `sizeof`, structs, enums, preprocessor
    - narrowing warnings for `long` → `int`
    - hex/octal literal suffix rules beyond decimal + L (can follow later)

Release goal:

    Programs can declare, pass, return, and compute with `long`; pointer
    difference is `long`; literals and promotions behave per C89 for the
    signed integer subset we support.

Current Compiler Shape (pre-long)
-------------------------------

Types (src/type.h / type.c):

    TY_VOID, TY_CHAR, TY_INT, TY_PTR, TY_ARRAY, TY_FUNC

    int  = 4 bytes, char = 1 byte, pointer = 8 bytes
    type_is_integer() = char | int only
    All integer binops in sema → type_int()
    type_assignable integers: any integer → any integer (silent)

Lexer (src/lexer.l):

    decimal [0-9]+ only, stored as long in yylval.num
    no L suffix, no 0x

Parser (src/parser.y):

    type: INT | CHAR | VOID | type '*'

Sema (src/sema.c):

    ND_NUM → type_int() always
    ptr - ptr → type_int()          ← will change to long
    integer promotions: not implemented (char/int collapse in practice)
    ICE / null pointer: int-centric

Codegen (src/codegen.c):

    int path: movslq / mov %eax / cdq+idiv / cltq after 32-bit ops
    pointer path: 64-bit %rax
    fits_i32 gates fast paths; oversized decimal uses slow 64-bit path
    ptr→int cast: movslq %%eax, %%rax (truncates pointer to 32 bits)


Locked Design Decisions
-----------------------

ID  Decision                                          Rationale
--  --------                                          ---------
D1  Option B: IntWidth + IntSign on integer types     Scales to unsigned/short
                                                      without another enum explosion.

D2  ptr - ptr → long                                  LP64 ptrdiff width; fixes
                                                      large-span subtraction.

D3  long → int assign: silent                         C89 3.3.16: may lose info;
                                                      no warning system required.

D4  Literal suffix L/l → long                         C89 3.1.5; explicit > guessing.

D5  Decimal without suffix: int if fits in int,       C89 3.1.5 integer constants.
    else long if fits in signed long, else error

D6  Codegen helpers refactored first                  Avoid sprinkling is_long in
                                                      ten ad-hoc paths.

D7  char promotes to int, not long                    C89 3.2.1 integral promotions.

D8  int + long → long (usual arithmetic)              C89 3.2.1 after promotions.

D9  long is 8 bytes, align 8 on x86-64                Matches SysV ABI and pointers.

D10 (long)p cast: preserve low 64 bits in %rax        Impl-defined value; full width.

D11 Do not alias long to int in the type system       Would break wrap semantics.

D12 Existing tests must keep passing                    Regression guard at every stage.


C89 Normative Anchors
---------------------

Section     Topic                         xcc obligation
-------     -----                         --------------
3.1.3       Integer types                 long int is signed integer type;
                                          width implementation-defined but
                                          ≥ range of int. Document 64-bit.

3.1.5       Integer constants             Unsuffixed decimal: int, else long,
                                          else unsigned long (reject if beyond
                                          signed long for now). Suffix L/l: long.

3.2.1       Arithmetic conversions        Integral promotion: values of type
                                          char/int → int. Usual arithmetic:
                                          if either operand is long after
                                          promotion, both become long.

3.2.2.1     Lvalue conversions            Unchanged; arrays still decay.

3.3.4       Casts                         Scalar-to-scalar; (long)e and (int)e
                                          allowed; narrowing impl-defined.

3.3.6       Additive operators            pointer ± integer; pointer - pointer
                                          → integer type (we choose long).

3.3.16      Assignment                    long → int allowed silently.

6.3.7       Function arguments            long passed per ABI (64-bit integer).

6.3.8       Function returns              long returned in %rax.


Proposed Type Model (Option B)
------------------------------

Replace flat TY_CHAR / TY_INT with a unified integer representation.

TypeKind (revised minimum):

    TY_VOID
    TY_INT      /* all integer types: char, int, long, later short/unsigned */
    TY_PTR
    TY_ARRAY
    TY_FUNC

New fields on Type (when kind == TY_INT):

    IntWidth width;    /* IW_CHAR, IW_INT, IW_LONG — IW_SHORT later */
    IntSign  sign;     /* IS_SIGNED for this feature; IS_UNSIGNED later */

Builtin singletons:

    type_char()  → TY_INT, IW_CHAR, IS_SIGNED
    type_int()   → TY_INT, IW_INT,  IS_SIGNED
    type_long()  → TY_INT, IW_LONG, IS_SIGNED

Size / align (x86-64 LP64):

    IW_CHAR → 1, align 1
    IW_INT  → 4, align 4
    IW_LONG → 8, align 8

Required new helpers:

    Type *type_long(void);
    int type_is_integer(Type *ty);
    int type_is_long(Type *ty);          /* width == IW_LONG */
    int type_int_width(Type *ty);        /* bytes */
    int type_int_rank(Type *ty);         /* for promotion: char < int < long */
    Type *type_int_promote(Type *ty);    /* integral promotion to int */
    Type *type_arith_convert(Type *a, Type *b);  /* usual arithmetic */
    int type_is_signed(Type *ty);
    const char *type_name(Type *ty);     /* "long", "char", "int" */

type_same / type_compatible / type_assignable:

    integers same iff width and sign match (sign always signed for now)
    assignable: same kind per C89 3.3.16 (including silent long→int)
    reject assigning integer to pointer except null constant rules (unchanged)

Migration from current TY_CHAR / TY_INT kinds:

    Stage 1 converts TY_CHAR/TY_INT → TY_INT + width/sign without behavior
    change. All existing switches on kind must be audited.


Codegen Refactor Plan (D6 — do before long semantics)
---------------------------------------------------

Introduce width-aware emit helpers in src/codegen.c (names indicative):

    int type_codegen_width(Type *ty);   /* 1, 4, or 8 for integers */

    void emit_load_slot(Type *ty, int off);
    void emit_store_slot(Type *ty, int off);
    void emit_load_mem(Type *ty);       /* *(rax) */
    void emit_store_mem(Type *ty);      /* *(rdi) */

    void emit_load_imm(long val, Type *ty);
    void emit_extend_to_rax(Type *ty);  /* char zext, int sext, long noop */

    void emit_binop(BinOp op, Type *result_ty);
    void emit_neg(Type *ty);
    void emit_cmp(BinOp op, Type *ty);

    void emit_reg_to_slot(const char *reg64, Type *ty, int off);
    void emit_arg_to_reg(Node *n, Type *ty, const char *reg64);

Rules:

    int (4):   32-bit ops in %eax, sign-extend to %rax for expr invariant
    long (8):  64-bit ops in %rax, no cltq
    char (1):  movzbl / movb (unsigned-byte storage model retained)

    comparisons: signed setcc family for all signed types (C89: no unsigned yet)

    div/mod:   int → cdq+idiv %edi; long → cqo+idiv %rdi

    pointer arg/return: unchanged 64-bit path (same as long)

Delete or narrow:

    fits_i32-only fast paths → gate on type_codegen_width == 4
    duplicated movslq/cltq blocks → centralize in emit_extend_to_rax


Lexer / Parser Changes
----------------------

Lexer:

    [0-9]+('L'|'l')?     → NUM token; flag or separate LONG_NUM token
    reject [0-9]+('U'|'u') for now (unsigned out of scope)
    reject invalid suffix combinations

    Store numeric value in yylval.num (long).
    Attach suffix flag: has_L_suffix.

Parser:

    type:
        LONG                { $$ = type_long(); }
      | INT                 { $$ = type_int(); }
      | CHAR                { $$ = type_char(); }
      | VOID                { $$ = type_void(); }
      | type '*'            { $$ = type_ptr($1); }

    declarator / param / cast unchanged structurally.


Sema Changes
------------

Literals (ND_NUM):

    if has_L_suffix → type_long()
    else if fits signed int → type_int()
    else if fits signed long → type_long()
    else → error "integer constant out of range"

Integral promotion (apply before usual arithmetic):

    char → int
    int → int
    long → long

check_arith_binop:

    promote each operand (char→int)
    arith_ty = usual_arithmetic_convert(lhs, rhs)
    n->ty = arith_ty

Pointer arithmetic:

    ptr ± integer: integer operand after integral promotion; scale unchanged
    ptr - ptr: n->ty = type_long()   /* D2 */

Unary minus:

    operand promoted; result type = operand type after promotion
    (negating long stays long)

Casts:

  (long)e:   scalar → long (integer promotions on operand first if applicable)
  (int)e:    scalar → int
  (long)p:   pointer → long, codegen keeps %rax
  (int)p:    unchanged (32-bit path) unless we revisit later

Returns / params / locals:

    use type_size/type_align from width fields
    long locals: 8-byte stack slots

ICE (ice_eval):

    evaluate in signed long range
  respect cast target width when folding


Known Deviations / Explicit Non-Goals
-------------------------------------

    - char remains unsigned at storage (movzbl); C89 signedness of plain char
      is implementation-defined. Document; signed char type comes with unsigned
      feature.

    - (int)p truncates pointer to 32 bits. C89 allows impl-defined conversion.
      (long)p is the full-width escape hatch (D10).

    - No unsigned long for unsuffixed overflow constants beyond signed long
      (C89 would use unsigned long next). We error instead until unsigned exists.

    - Integer promotions are not the full C89 set (no unsigned, no short).
